# Archetype character art

Notes for whoever rebuilds this art. Kept in docs/ rather than beside the
files: anything under public/ is served, and these notes are internal.

Generated by `scripts/build-archetype-art.mjs` from the 16 source illustrations in
`~/Downloads/MBTI/v2/`, named by archetype code. The sources are ~1024x1536 and
1.3-1.7 MB each; only the derived WebP is committed.

**Art only, never text.** These sources are plain figures on white with nothing
written on them, which is what makes them safe to use. An earlier set arrived
as finished cards with the name, weakness, dominant pole and chapter numbers
printed on the picture, and that text contradicted `lib/grade/archetypes.ts`:
`CSKO`, `CSKG` and `CSRO` all carried the same pasted block reading
`R - เปลี่ยนวิธี` with chapters `4.2 • 3.3 • 5.2`, though `R` is in neither
CSKO's nor CSKG's own code and `5.2` is a premium chapter the public result
page must never link to. Two archetypes were named differently again, and the
footer branded them CONTRA MINDSET.

So every word on the result page comes from `archetypes.ts`, where the tests
already forbid those mistakes. Keep it that way: art that makes claims cannot
be tested, and it goes stale the moment the data changes.

## Cutting out the backdrop

The white is removed in two passes.

First, flooding inward from the border rather than testing each pixel for
brightness — several figures wear white or pale grey (HIKG's cream
cloak, HSRO's tan robe) and a luminance threshold punches holes through them.

Second, clearing pockets the flood cannot reach. Windswept hair encloses
islands of backdrop — HIRG had 207 of them, 8,865 pixels — and an edge flood
never gets in. What separates them from genuinely pale clothing is flatness:
those pockets average luminance 251 at saturation 1.5, while HIKG's cream
cloak produced no pocket bigger than a few pixels. A pocket is cleared when at
least half of it is that flat white; judging every pixel instead disqualified
all 207, because each pocket fades into the hair around it.

Edge pixels are then un-mixed. A half-transparent boundary pixel captured
`C = a*F + (1-a)*255`, and leaving that white in gives the figure a pale rim
against a dark page, so F is solved for directly.

Two sharp APIs look right for applying the resulting mask and both fail
quietly, which cost an hour:

- `composite` with `blend: "dest-in"` reads a one-channel input as greyscale
  *colour* at full opacity, so it keeps every pixel and the cutout does
  nothing at all. The output still reports `hasAlpha: true`.
- `joinChannel` yields a four-band image that sharp does not necessarily treat
  as RGBA, which lands the mask visibly out of step with the picture.

The mask is therefore written straight into the fourth byte of each pixel and
handed to sharp as `raw` RGBA. `trim()` was also dropped — it cropped a
standing figure to a 1024x583 letterbox — in favour of computing the opaque
bounding box directly.

## Rebuilding

    node scripts/build-archetype-art.mjs --sheet

`--sheet` writes a 4x4 grid one directory above the repo so all sixteen can be
checked together. Use it: every failure above looked plausible file-by-file and
was obvious the moment the whole set was laid out side by side.

After rebuilding, clear `.next/cache/images` — the dev server keeps serving the
previously optimised copies otherwise, and you will think nothing changed.

## Card frames

Four ornate frames back the result card, at `public/quiz/frames/`. Which one an
archetype gets is decided by `frameFor()` in `lib/grade/archetypes.ts` from the
first and third letters of the code — the two axes that say *how* the damage
arrives:

| frame  | letters | meaning                        |
|--------|---------|--------------------------------|
| green  | C + K   | cuts losses, keeps one method  |
| purple | C + R   | cuts losses, switches methods  |
| navy   | H + K   | holds losers, keeps one method |
| gold   | H + R   | holds losers, switches methods |

Sixteen archetypes therefore need only four frames, and the colour carries
information rather than decoration. A test asserts each colour covers exactly
four codes that agree on both letters, so the scheme cannot quietly rot.

The parchment inside every frame is cream whatever theme the site is in, so
text drawn on the card uses fixed colours — never the theme tokens, which flip
in dark mode and would turn the card's type white on cream.
