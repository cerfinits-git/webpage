## 2. ข้อจำกัดที่ยอมรับไว้ล่วงหน้า

### 2.1 MBTI ของจริงไม่ผ่าน Evidence Gate

- test-retest ต่ำ — ผู้ทำแบบทดสอบราวครึ่งหนึ่งได้ type ต่างจากเดิมเมื่อทำซ้ำในเวลาไม่กี่สัปดาห์
  (Pittenger, *Consulting Psychology Journal* 2005)
- ไม่มีหลักฐาน bimodality — คะแนนกระจายต่อเนื่อง การตัดที่กลางทำให้คนคะแนน 49 กับ 51
  ถูกจัดคนละประเภท
- แกน E/I, S/N, T/F, J/P ไม่มีตัวใดถูก validate ว่าพยากรณ์พฤติกรรมการลงทุนได้

**ผลต่อการออกแบบ:** ยืมเฉพาะ**รูปแบบการนำเสนอ** (ป้ายประเภทที่แชร์ได้) ไม่ยืมแกนของ MBTI
และแก้จุดอ่อน bimodality ด้วยการ**แสดงคะแนนเป็นสเกลต่อเนื่อง** พร้อมระบุชัดเมื่อผู้ทำอยู่กลางแกน

### 2.2 เพดานของช่องทาง

followers 8,000 · reach 300–1,000/โพสต์ → คาดได้ **~10–40 email ตลอด 30 วัน** ไม่ใช่ 100
สเปกนี้ออกแบบบนสมมติฐานนั้น ไม่ได้สมมติว่าจะไวรัล

### 2.3 ขอบเขตทางกฎหมาย

ผลลัพธ์**อธิบายพฤติกรรม** ห้ามแนะนำการลงทุนรายบุคคล — ห้ามคำว่าซื้อ/ขาย/ถือ/รอ,
ห้ามแนะนำสินทรัพย์รายตัว, ห้ามอ้างว่าทำนายผลตอบแทนได้ (สอดคล้อง R11 ของสเปก `/research`)
ต้องมี disclaimer บนหน้าผลลัพธ์และก่อนกรอก email

## 3. แกน (ล็อก) — 4 แกน 24 ข้อ 16 ประเภท

> **แก้ไข 2026-08-14 (Kan สั่ง):** จากเดิม 2 แกน / 8 ข้อ / 4 ประเภท เป็น
> **4 แกน / 24 ข้อ / 16 ประเภท** — ยกเลิกข้อจำกัด "ไม่ทำ 16 ประเภท" ในหัวข้อ 8

เลือก 2 แกนเพื่อให้ต้นทุนคอนเทนต์เท่ากับ 4 ชุด (ไม่ใช่ 16) และทั้งสองแกนยึดกับ
พฤติกรรมที่มีวรรณกรรมรองรับ ไม่ใช่บุคลิกภาพลอย ๆ

| # | แกน | ขั้ว | ฐานที่ยึด |
|---|---|---|---|
| 1 | ปฏิกิริยาตอนขาดทุน | `C` ตัด ↔ `H` ถือ | **disposition effect** — Shefrin & Statman 1985; Odean, *Journal of Finance* 1998 พบว่านักลงทุนรายย่อยขายตัวที่กำไรในอัตราสูงกว่าตัวที่ขาดทุนอย่างมีนัยสำคัญ |
| 2 | ที่มาของความมั่นใจ | `S` ระบบ ↔ `I` สัญชาตญาณ | **ต้นทุนการเทรดถี่** — Barber & Odean, *Journal of Finance* 2000 พบว่ากลุ่มที่ซื้อขายถี่ที่สุดได้ผลตอบแทนสุทธิต่ำกว่าตลาดอย่างมีนัยสำคัญ |
| 3 | ความสม่ำเสมอของวิธี | `K` คงวิธี ↔ `R` เปลี่ยนวิธี | **recency bias** — ทิ้งวิธีระหว่าง drawdown ที่ยังอยู่ในช่วงปกติ ผลที่วัดได้จึงไม่ใช่ผลของวิธีใดเลย |
| 4 | ที่มาของไอเดีย | `O` คิดเอง ↔ `G` ตามกลุ่ม | **herding** — รับสัญญาณโดยไม่ผ่านเกณฑ์ของตัวเอง = รับความเสี่ยงที่ไม่ได้ประเมินเอง |

ตัวอักษรทั้งแปดต้องไม่ชนกัน (มีเทสต์บังคับ) ไม่งั้นถอดรหัสกลับเป็นแกนไม่ได้

### ตาราง 16 ประเภท

รหัส = `[ตัด/ถือ][ระบบ/สัญชาตญาณ][คงวิธี/เปลี่ยนวิธี][คิดเอง/ตามกลุ่ม]`

| code | ชื่อ | ขั้วเสี่ยงหลัก |
|---|---|---|
| `CSKO` | วิศวกร / The Engineer | `S` กฎที่ยังไม่พิสูจน์ว่าเป็นบวก |
| `CSKG` | ผู้ปฏิบัติตามคู่มือ / The Technician | `G` กฎของคนอื่นที่ไม่เคยตรวจสถิติ |
| `CSRO` | นักทดลอง / The Experimenter | `R` เปลี่ยนกฎก่อนวัดผลได้ |
| `CSRG` | นักไล่ตามระบบ / The System Chaser | `R` ระบบใหม่จากแหล่งใหม่ทุกครั้ง |
| `CIKO` | นักอ่านเกม / The Reader | `I` วิธีอยู่ในหัว ตรวจย้อนหลังไม่ได้ |
| `CIKG` | ลูกศิษย์ / The Disciple | `G` ความมั่นใจมาจากตัวบุคคล |
| `CIRO` | นักล่าจังหวะ / The Sprinter | `I` overtrading — ต้นทุนต่อรอบคูณจำนวนรอบ |
| `CIRG` | นักไล่สัญญาณ / The Signal Hopper | `G` ต้นทุนสูงสุดและไม่มีอะไรสะสม |
| `HSKO` | สถาปนิก / The Architect | `H` มีกฎแต่ไม่ทำตามตอนขาดทุน |
| `HSKG` | ผู้ยึดแนวทาง / The Loyalist | `H` ถือต่อเพราะกลุ่มรับรอง |
| `HSRO` | นักแก้กฎ / The Rule Bender | `R` แก้กฎระหว่างถือไม้ |
| `HSRG` | นักหาเหตุผลใหม่ / The Rationaliser | `H` เปลี่ยนกรอบให้ไม้ที่ติดลบมีเหตุผล |
| `HIKO` | ผู้ศรัทธา / The Believer | `H` ถือด้วยความเชื่อ ไม่มีจุดออก |
| `HIKG` | ผู้ร่วมขบวน / The Passenger | `G` ถือตามกลุ่มโดยไม่มีเกณฑ์ |
| `HIRO` | นักเสี่ยงโชค / The Gambler | `H` ผลถูกกำหนดโดยไม้ใหญ่ไม่กี่ไม้ |
| `HIRG` | ผู้ตามกระแส / The Drifter | `G` ความเสี่ยงสูงสุดในสี่แกนรวมกัน |

**ทุกประเภทมีจุดอ่อนเขียนกำกับ และทุกขั้วมีต้นทุน** ไม่มีประเภทใดเป็น "ประเภทที่ดีที่สุด" —
ถ้าเขียนให้ประเภทหนึ่งชนะ แบบทดสอบจะกลายเป็นคำแนะนำ

**หลักฐานผูกกับขั้วของแกน ไม่ใช่กับ 16 ประเภท** — งานวิจัยรองรับพฤติกรรมที่วัด
ไม่ได้รองรับป้ายที่เราตั้งชื่อขึ้นมา การเขียนงานวิจัยแยก 16 ชุดจะเป็นการกุ

## 4. โครงหน้าและ flow

```
IG @Crzin_s (link in bio → /quiz)
  → 24 คำถามสถานการณ์ (6 ข้อ × 4 แกน, ไม่ต้องล็อกอิน, ~4 นาที)
  → หน้าผลลัพธ์: รหัส 4 ตัว + สเกลต่อเนื่องสี่แกน + จุดอ่อน + หลักฐานของขั้วเสี่ยงหลัก
  → 3 บทเรียน /grade ที่ตรงกับจุดอ่อน (ลิงก์ตรง, ระดับ 1–4 ฟรี)
  → กรอก email (ไม่บังคับ — เห็นผลก่อนเสมอ)
  → ปุ่มคัดลอกลิงก์ + ข้อความชวนแคปหน้าจอแชร์ IG story
```

**ความเสี่ยงที่ยอมรับไว้:** 24 ข้อใช้เวลา ~4 นาที เทียบกับ 90 วินาทีของเวอร์ชัน 2 แกน
อัตราเล่นจบจะต่ำลง ซึ่งกระทบตัวชี้วัด acquisition โดยตรง แลกกับการวัดที่เที่ยงกว่า
(6 ข้อต่อแกน แทน 4) และป้ายที่แชร์แล้วน่าสนใจกว่า — Kan ตัดสินใจ 2026-08-14

**ข้อบังคับ:** ห้ามมี login gate หรือ email gate ก่อนเห็นผล — ปิดกั้นตรงนั้นคือฆ่า funnel

## 5. เก็บข้อมูล

ต่อยอด `/api/newsletter` เดิม (มี honeypot อยู่แล้ว):

```ts
type NewsletterSignup = {
  email: string;
  at: string;
  source?: string;    // "quiz"
  archetype?: string; // รหัส 4 ตัวจาก 16 แบบ เช่น "CSKO"
}
```

เก็บ **เฉพาะ code ของประเภท** ไม่เก็บคำตอบรายข้อ — พอสำหรับเช็ค kill criteria
โดยไม่สร้างกองข้อมูลพฤติกรรมที่ต้องดูแล

ตาราง Supabase `newsletter_signups` มีคอลัมน์ `source` / `archetype` แล้ว
(migration `supabase/newsletter_attribution.sql` รัน 2026-08-14) พร้อม check constraint
จำกัดค่า archetype ไว้ที่ 16 รหัสที่ถูกต้อง

**ต้องทำก่อนโพสต์ครั้งแรก:** ข้อความแจ้งการเก็บข้อมูลใต้ช่อง email (PDPA — email
เป็นข้อมูลส่วนบุคคล) และ Privacy Policy ซึ่งเว็บยังไม่มี

## 7. Kill criteria (ล็อก)

โพสต์ชวนเล่น **3 ครั้งใน 30 วัน** แล้ว:
